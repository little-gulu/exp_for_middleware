KRaft：Kafka 的无 ZooKeeper 架构

新版本 Kafka 用一套 controller 节点（Raft 共识）替代了 ZooKeeper。记住这张图就抓住了一个核心：数据走 Broker，元数据走 Controller——两条平面，各走各的。

怎么读这张图

  1. 1两条平面，各走各的。生产者/消费者只碰 Broker，永远不直接找 Controller；Broker 需要元数据（建 topic、选分区 leader）时才去问 active controller。
  2. 2副本分散、Leader 唯一。每个分区（P0/P1/P2）在 3 个 Broker 上各有一份副本，但只有一个是「主」，读写都打到主，其余「从」只同步。这就是之前说的「一 broker 一机 + 副本跨机」。
  3. 3Controller 是投票团，不是单个机器。3 个 controller 组成 Raft，只有 Controller 1（active）在职，其余 standby。元数据日志靠 Raft 复制多份，active 挂了 standby 立即接班。
  4. 4ZooKeeper 彻底消失。旧版里 ZooKeeper 负责存元数据、选 controller；新版把这活儿内建进 Kafka 自己的 Controller quorum，少一层外部依赖。
